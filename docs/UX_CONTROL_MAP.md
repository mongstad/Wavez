# Current-to-proposed control map — issue #14

Design-only; pending owner review. Baseline `68e3b5abb548d2e95ba5ae5b8e57e03d652de502`.
[Architecture](UX_INFORMATION_ARCHITECTURE.md) and [review](UX_IA_REVIEW.md) define the
proposal and evidence limits. Grouped rows enumerate each constituent control;
dynamic object/channel/type rows apply once per supported source entry. Godot
internal picker widgets inherit the named picker operation, validation and cancel
contract. Hidden controls remain inventoried; there is no removal by omission.

`IA-NNN` are **proposed traceability IDs**, not implemented semantic command IDs.
The existing symbol is a source binding, not a new API. Most production controls
have no semantic UI ID. Existing model keys are recorded below; visible slider and
section labels are also legacy serialized identities. Do not rename those keys
when adopting proposed wording. Native helper labels and local variables locate
controls even when their current UI has no adjacent label.

Scope is the first column; destination names one canonical editing home (read-only
summaries may repeat). Disclosure: always / contextual / named secondary /
diagnostic / documentation. Common/occasional are design judgments, not telemetry.

State legend: **V** means current visual state in v2, v3 visual snapshot and frozen
video; **A** means committed v3 analysis/selection state, with drafts session-only;
**S** means current session state, not newly persisted; **J** means session job form
frozen into a job at explicit start. These describe ownership, not promises that
every display label is serialized. See [exact ownership](../INSPECTION_STATE.md).
No reset is implied by moving a control. Explicit resets/clear/delete actions are
scoped in their row; otherwise retain current defaults and restoration semantics.

Gates R01–R13 refer to the [existing regression matrix](UX1_REGRESSION_WORKFLOWS.md).
Additional volume/probe gates are `tools/validate_volume_color.py`,
`tools/validate_volume_opacity.py`, `tools/validate_volume_presets.py`,
`viewer/layers/test_probe_marker.gd` (source path verified during review), and
`tools/validate_recipe_state.py`; camera and background-export tests protect recent
maintenance. These are **future migration gates**, not tests run for this design.

## Completeness and explicit unresolved work

The map covers the main shell/shortcuts, dynamically built layers/buffers, all
selection and analysis setup factories, plots/results, file dialogs and video form.
Source-derived inventories include unavailable actions and dynamic option families;
static rows are not a claim of a fixed runtime widget count. Scalar plots and
heatmaps retain their source/hover readouts and exact values even when expanded.
CLI-only settings and the development-only UX2 laboratory are not production UI
controls; neither is being removed or migrated.

Two presentation additions need implementation decisions: last-probe time/channel
must be stamped when probing (not guessed from playback), and Analysis must expose
shared request inputs locally without accidentally cloning independent values.
All controls have destinations; these unresolved bindings do not justify omission.

The proposed State menu has typed scene and analysis operations. Export owns PNG,
video and numerical output. Avoid duplicate editable recipe forms; task-context
links may navigate to those canonical actions. Matched views keep their complete
request form in Analysis, with status/reopen/cancel in Jobs.
