# UX1 — Regression-sensitive workflows

These are gates for future UX changes, grounded in the accepted SIMSCP3 / `.ssc` product. They are **not a claim that UX1 reran the full release suite**. UX1's actual validation is recorded in the [report](UX1_REPORT.md). See [audit risks](UX1_UI_AUDIT.md#coupling-and-technical-risk-inventory) and [component contracts](UX1_DESIGN_SYSTEM.md#component-and-state-architecture).

## Future test selection

Run checks proportional to changed boundaries. Theme-only foundation: parse/import, component state showcase, contrast/layout/focus and snapshot immutability. Consumer moves: the associated workflow gates plus old native recipe round trips. Render/export-boundary edits: both Forward+ and Compatibility, viewport-only comparisons and explicitly reviewed UI-overlay changes. Worker/source changes require lifecycle, cancellation and bounded-memory coverage even if the visible change looks small.

Use current synthetic generators (`examples.scene_demo --small`, `examples.identity_demo`) and explicit frozen external capture paths. Do not regenerate scientific benchmark simulations. Keep raw captures, videos and traces ignored/outside Git; retain small summaries, hashes and selected screenshots. Do not overwrite historical screenshots or benchmark evidence to make a new baseline pass.

External benchmark integrations and scientific source projects live outside this repository. Use explicit frozen capture paths for regression work and do not relabel historical evidence as a newly rerun scientific validation.

## Review procedure for a later UI change

Capture the starting commit and existing dirty files. Identify affected C/U/R IDs. Record intentional UI pixel/placement changes separately from sampling and scientific-state invariants. Preserve baseline native recipes and exact-value examples. Run the relevant existing validators with fresh output directories, then execute keyboard/mouse and scaling cases that automation does not cover. Report failures as introduced, pre-existing/reproduced, or unverified. Never call a visual audit screenshot or an old accepted benchmark a fresh scientific regression pass.

Stop at the authorized milestone's review gate. This document schedules no automation and starts no UX2–UX9 implementation.
